Clearify — Analysis Pipeline

Grounding, anti-hallucination, and failure handling of the news-analysis flow · v1.0.0   2026-10-18 · verified against source

Clearify analyzes the news article in the active tab, grounds the analysis in live, keyless web search, and renders bias dimensions, framing, omissions, and three perspective cards (progressive / mainstream / conservative) in a side panel. Every perspective must cite a source that was literally gathered by the search layer — citations the model invents are stripped in code before the result is ever displayed.

Cancellation & lifecycle

  • One AbortController per run; CANCEL_ANALYSIS aborts it. Every fetch is wired to the same signal — user aborts surface as {cancelled} and restore the previous panel state, never as an error.
  • MV3 module state resets on worker restart — by design: a dead run cannot resume, the pending panel message surfaces as "Analysis interrupted", lastResult rehydrates from storage, and a fresh run is never fenced off by a stale isAnalyzing flag.
  • All chrome.runtime/chrome.tabs messages verify sender.id === chrome.runtime.id; content scripts are low-trust and passive.

2. The grounding layer — keyless search

utils/search.js. Two free engines, no API keys, no accounts. Query = the story headline; when a page has no usable headline (paywall, SPA shell) it falls back to the first 14 words of article text. The outlet name is deliberately excluded from the query — searching for it would bias results toward the page the user is already reading, the opposite of what the perspective cards need.

SourceBehaviorKnown failure mode → handling
Google News RSS (primary)news.google.com/rss/search?q=…&hl&gl&ceid. Aggregates one story across many outlets — exactly the multi-outlet coverage the perspective cards need. Each item yields: headline (outlet suffix split off), a working news.google.com redirect URL, the outlet's own homepage URL, and a date. The page's lang tag maps to a regional edition (en-NG → hl=en&gl=NG&ceid=NG:en), so a Nigerian story surfaces Nigerian outlets; malformed tags fall back to the US edition.302 normalization stays on the same host (covered by the manifest permission); unsupported edition params degrade to fallback, then to an ungrounded run.
DuckDuckGo HTML (fallback)html.duckduckgo.com/html/?q=… — general web results, redirect links (?uddg=) unwrapped to real article URLs, HTML entities decoded.Bot challenge answers with HTTP 202 — ok is true for 202, so it is recognized by status; the anomaly page is never mistaken for a result set. (This silent-failure mode is what originally caused the pipeline to hallucinate perspectives.)

Zero results from both engines → the analysis still runs, but ungrounded: the prompt switches to its ungrounded variant, webEnriched:false is stored, and the panel badges the result ⚠ NO SOURCES. Search failure is never silent in the UI again.

3. The two prompt variants

Grounded (coverage found) — the prompt embeds the numbered coverage entries with their exact URLs and contracts: judge omissions only against facts evident in the entries; every perspective's url must be copied character for character from a listed entry; no fitting source → 'N/A' for both source and URL.
Ungrounded (no coverage) — the prompt states that no live coverage was retrieved, forbids inventing outlets, URLs, headlines, or coverage claims, requires 'N/A' attribution, restricts omissions to gaps evident from the article text itself, and requires perspective summaries to read as general background context — never as how specific other outlets reported the story.

The response shape is identical in both variants: credibility score 0–100, four bias dimensions, framing, omissions[], and the three perspective cards (source / url / summary each).

4. The anti-hallucination stack

LayerMechanismWhat it prevents
1Keyless live search (GNews RSS → DDG fallback)Perspectives written purely from model priors: the model sees real, current, multi-outlet coverage of the same story — no provider key or search tool required.
2Prompt contracts (§3)Unforced invention: exact-URL copying in the grounded case; explicit no-invention and N/A rules in the ungrounded case.
3Code-side citation validationModel drift: validatePerspectiveCitations blanks any perspective URL not literally among the gathered article/outlet URLs, and blanks outlet names that match no gathered source (a kept exact URL vouches for its card). Enforced after parsing, before caching — prompt obedience is not trusted.
4Honest UIIndistinguishable fabrication: 🔍 WEB vs ⚠ NO SOURCES badge tells the user whether perspectives carry live sources; only http(s) URLs render as links; the link label is the real hostname; empty cards dim to 0.35 opacity instead of inventing content.

5. Network guards — fetchWithGuards

  • Timeout: 60s for provider calls, 15s for search. Timeout throws a friendly "pick a faster model" message, distinct from cancellation.
  • 429/503: exactly one retry; the server's Retry-After hint is honored, capped at 8s so a hostile header can never stall a run.
  • Transient network errors (ECONNRESET, ETIMEDOUT, "fetch failed"): one retry before surfacing — persistent failures still fail fast.
  • User aborts: propagate as AbortError, mapped to {cancelled}, never reported as failure.
